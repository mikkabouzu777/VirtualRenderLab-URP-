# VirtualRenderLab

UE5 の 3 つの描画技術を、公開されている考え方だけを元に Unity(6000.3.27f1・URP 17.3)で自作した試作です。UE のコードは使っていません。
PC の観客用画面で使うことを想定しています。PICO 単体では動かす前提にしていません(D3D11/12 で確認)。

| シーン | 中身 | 確かめた数字(RTX 3080 Laptop・1600x900・エディタ) |
|---|---|---|
| `Assets/VRL/Scenes/1_Meshlet` | 32 万三角形の岩 160 個。三角形を塊(64 頂点/124 三角形)に分け、Nanite のような継ぎ目のない LOD(DAG・14 段・QEM で減らす)に組む。GPU で物 → 段 → 塊と絞り、塊ごとに「画面の誤差 1px 以下の一番粗い段」を選んで、視錐台・裏向き・Hi-Z(隠れた塊)で外す。画面で小さい塊は compute で塗る(ソフトウェアラスタ)、大きい塊は普通に描く | 描く三角形 222 万(全部元の形なら 5,243 万)、うち 216 万はソフトウェアラスタ。Hi-Z で外せる塊は見えている物の約 64%。調べる塊は全部の 41%(合体シーンでは 19%)。DAG はファイルから 15 ms で読む(組むと約 2.9 秒) |

## 使い方
- シーンは道具で作り直す: メニュー `Mikkabouzu/VirtualRenderLab/シーンを作る/…`(手で直した物は作り直すと消える)
- URP の設定(深度を先に描く・VSM の Renderer Feature): `Mikkabouzu/VirtualRenderLab/URP を設定し直す`
- 共通の操作: 右ドラッグ=見回し / WASD・QE=移動 / Shift=速く / P=自動周回 / H=情報の出し入れ

| キー | Meshlet | VSM | RVT |
|---|---|---|---|
| 1〜 | 仕上がり/塊/三角形/DAG の段/物/Hi-Z の 2 回目で描いた塊/ソフトウェアラスタで塗った塊 | 仕上がり/ページ/レベル/このコマ描き直したページ | 仕上がり/mip/物理のマス/届いたか |
| その他 | K=段を固定 / [ ]=許す誤差(px) / O=Hi-Z / R=ソフトウェアラスタ / C=裏向きで外す / F=外す判定を止める / X=影 / M=普通の描画と比べる | V=URP の影と比べる / N=持ち越しの入切 / [ ]=レベルのずらし | B=毎画素計算と比べる / [ ]=mip のずらし / R=焼き直し |

合体シーン: 1=仕上がり 2=Meshlet 塊 3=Meshlet DAG の段 4=VSM ページ 5=VSM 描き直し 6=RVT mip 7=Hi-Z の 2 回目 / V=VSM↔URP / N=VSM 持ち越し / B=地面 RVT↔毎画素 / F=岩の外す判定を止める / O=Hi-Z / R=ソフトウェアラスタ

Meshlet の仕組み(`Assets/VRL/Meshlet/`):
- `MeshletDag.cs`: 隣り合う塊を 4 つずつまとめ、まとまりの外周の頂点は動かさずに中だけ三角形を半分へ減らして、また塊に分ける。これを塊が 1 つになるまで繰り返す。外周を動かさないので、隣が細かいままでも隙間ができない。減らし方は QEM(辺をつぶす。元の面からの離れ方を二次式で見て、安い辺から。裏返る物はつぶさない)
- `MeshletDagCache.cs`: 組んだ DAG を `Application.persistentDataPath/VRLCache/` に保存し、次からは読むだけ(組み方を変えたら中の Version を上げる)
- 物 → 段 → 塊の順に絞る(`CullInstances`): 物の球までの距離の幅から、切り口に入りうる DAG の段だけを (物, 段) として並べ、その段の塊だけ調べる。Nanite は塊の木(BVH)で絞るが、ここは 2 段の簡単な絞り方
- ソフトウェアラスタ(`SwRaster*`): 球の半径が 12px より小さい塊は、三角形を compute で塗る。1 回目は深度だけ InterlockedMax、2 回目は深度が一致した画素に (塊, 三角形) を書く。そのあと全画面の三角形 1 枚で、深度テクスチャへ書き足し(`SwDepth`)、不透明の後に色を付ける(`SwResolve`)。ハードの描画とは深度でまざる。URP の普通の影には、ソフトの塊も影だけハードで描く(影だけ通す材質の写しで)
- Hi-Z は 2 回調べる: 1 回目(LateUpdate)は前のコマの深度ピラミッドで外し、隠れていた塊は取っておく。2 回目(`MeshletFeature`、深度を先に描いた直後)はこのコマの深度で作り直したピラミッドでもう一度調べ、見えた塊を深度へ描き足して、不透明の後に色を描く。これで、急に振り向いても穴が開かない(検証用の `debugAllToPost` で、2 回目だけでも同じ絵になることを確かめた)
- Renderer に `MeshletFeature`(Hi-Z の 2 回目とソフトウェアラスタ)が要る。`URP を設定し直す` で足される。どちらもメインカメラだけなので、シーンビューでは隠れていた塊とソフトの塊が抜けて見える
- URP の普通の影(VSM を切った時と 1_Meshlet)は、1 回目の塊とソフトの塊しか描かない。カメラから外した・隠れた岩の影が欠けることがある
- 罠: ソフトの塊はグループ数の上限 65,535 を超えるので 2 次元で回す(超えた分が塗られず穴 → 穴のある深度で Hi-Z が効かず塊が増える、の悪循環で抜けられなくなった)。全画面で描く所には物ごとの環境光が来ないので、シーンの環境光(SH)を C# から渡す

GPU 時間について: エディタの HUD の GPU 時間(FrameTimingManager)はぶれが大きく、処理ごとの GPU 時間(Recorder / ProfilerRecorder の GPU 計測)は 0 しか返らなかった。VSM の持ち越しの効果は「描き直したページ数」と「影に描いた三角形数」で見ている。ms で比べるならビルドして GPU プロファイラ(PIX / RenderDoc)で。

## まだ無いもの(次の段)
- Meshlet: 塊の木(BVH)で物の中もまとめて外す / ソフトウェアラスタの材質ごとの色付け(今は全画面 1 枚で岩の色だけ)/ 64bit の InterlockedMax で深度と番号を 1 回で書く
- VSM: 動く物が多い時の描き直しの絞り込み(今は動いた物の外接球が掛かるページを丸ごと)/ 点光源 / 持ち越しはメインカメラ 1 台ぶん(シーンビューはその結果を読むだけ)
- RVT: 法線・粗さの層 / mip の間の補間 / 道や岩を後から描き込む仕組み
- 合体: 観客アプリへの組み込み
